# 内存与稳定性实测记录

所有数字为**真机实测**（Windows 11 x64，同一台机器上分别运行 32 位与 64 位产物），
采集方式为进程内 `GetProcessMemoryInfo`（PSAPI）+ `runtime.ReadMemStats`，并用外部 `Get-Process` 复核。

复现命令：

```powershell
# 分阶段（0=空窗 1=播放列表 2=播放中 3=歌词 4=评论 5=评论第 2 页）
netmusic32.exe -selftest -stage 5

# 长跑（N 次切歌，每轮采样）
netmusic32.exe -soak 10
```

> exe 是 GUI 子系统，从命令行采集输出需要显式重定向：
> `Start-Process .\netmusic32.exe -ArgumentList '-selftest','-stage','5' -RedirectStandardError log.txt`
> 进程内采样比任务管理器（会四舍五入到整 MB）精确。

### 1.2 评论模块开启前 / 后

| | 评论前 (stage3) | 评论后 (stage4) | 增量 |
|---|---|---|---|
| **RSS** | 35.42 MB | 36.26 MB | **+0.84 MB** |
| 私有字节 | 20.94 MB | 21.48 MB | +0.54 MB |
| Go Heap | 6.06 MB | 6.37 MB | +0.31 MB |
| GDI 对象 | 46 | 48 | +2 |

阈值是「超过 20MB 就降级为只显示热门前 N 条」；实测 **0.84MB**，因此**未降级**，热门/最新/分页全部保留。
翻到第 2 页后 RSS 反而下降 0.02MB（GC 抖动），证明**翻页不累积内存**。

## 3. 32 位与 64 位的差异说明

- **私有字节差 3 倍**（21MB vs 64MB）：主要是 64 位进程的地址空间保留与指针膨胀。RSS 只差 3MB。
- 因此 2GB 内存的 Win7 机器上，**优先分发 32 位版**：RSS 更低，且能跑在 32/64 位系统上。

## 5. 测量可信度说明

- RSS 用 `GetProcessMemoryInfo().WorkingSetSize`，与任务管理器「内存(专用工作集)」同源；私有字节用 `PrivateUsage`，与
  Process Explorer 的 `Private Bytes` 同源。
- Go 侧数字来自 `runtime.ReadMemStats`，只反映 Go 堆，**不包含** GDI 位图与 DLL 页，所以表格里两项都列出来。
- 唯一无法在本机验证的是 Win7 本身的内核/图形栈差异（本机是 Win11）。已通过「32 位产物 + 只用 Vista 起就存在的 API +
  Go 1.20 运行时」把可验证的部分压到最小；剩余风险见 README「已知限制」。
